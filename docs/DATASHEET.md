# SecOps-2k datasheet

Short form of Gebru et al., "Datasheets for Datasets." Grouping policy is in
`GROUPING-RULES.md`. Machine-readable templates are in `configs/templates.yaml`.

## Motivation

Parser papers still report numbers on LogHub system logs (HDFS, BGL, Apache).
Security / operations lines (sshd, sudo, UFW, auditd) are missing from that
monoculture. SecOps-2k is a 2,000-line synthetic set in LogHub format so a
parser can be scored on that domain without shipping real host data.

## Composition

- 2,000 syslog-shaped lines, one host (`secops-01`), one day (14 Jun).
- 25 tight templates, 10 loose groups. Two ground-truth CSVs; only `EventId`
  differs. `EventTemplate` is identical, so parsing accuracy is the same and
  grouping metrics show the grouping effect.
- Processes: sshd, sudo, kernel (UFW), audit. Tokens that vary at runtime are
  `<*>`. IPv4 literals are RFC 5737 documentation ranges or RFC 1918 private
  space.
- Lines are drawn independently from template weights. There is no session
  correlation, clock skew, or unrelated daemon noise.

## Collection

Generated by `scripts/generate.py` from `configs/templates.yaml`. Default seed
and length live in that yaml (`seed: 42`, `n_lines: 2000`). The committed
`dataset/` files are the artifact; they must match a regen from those defaults.
No production logs were copied or anonymized.

## Uses

Intended: comparing log parsers (Drain and later work) under tight vs loose
ground truth, using GA / PA / FGA / FTA.

Not intended: training intrusion detectors, claiming coverage of real SOC
traffic, or treating the Drain table as a leaderboard for detection quality.

## Maintenance

MbitAI, Apache-2.0. Grouping-rule changes go through `CONTRIBUTING.md`. Drain
settings in `configs/drain.yaml` are pinned; do not retune to chase the golden
file. Contact via https://github.com/TMFNK/LogParser-Dataset/issues.
